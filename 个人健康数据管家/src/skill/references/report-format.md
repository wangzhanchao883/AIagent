# 日报版式与判定口径

> 改 `build_report.py` 前先读这份。版式是**已定版**的，不要随手改结构。

## 一、三层结构

```
第一层「一眼看明白」
  ① 一句话总结      ← 总判断 + 三行判定 + 体重总趋势图 + 今日建议三块
  ── 分隔线「详细指标如下」
  ② 核心指标总览    ← 体检化验单样式
  ③ 近 14 天趋势    ← 12 张小折线图，分三组（身体形态 / 营养摄入 / 活动与恢复）
  ④ 热量账本        ← 支出拆解 + 缺口区间
  ⑤ 饮食结构是否合理
  ⑥ 睡眠情况
  ⑦ 今日建议        ← 完整规则建议（头部只给摘要，这里给全文）
  ⑧ 昨日建议执行率（T+1 对比）
── 分割线 ──
第二层「明细」
  ⑨ 餐食明细 ⑩ 运动明细 ⑪ 体重趋势（近 30 天） ⑫ 睡眠分期
  ⑬ 恢复与体征 ⑭ 个人份量库 ⑮ 数据来源与局限
```

## 二、① 一句话总结（D-38 定版）

**结构**：一句总判断 → 三行判定（饮食结构 / 睡眠 / 运动）→ 今日建议三块

| 块 | 要求 |
|---|---|
| 一句总判断 | 由三行状态自动汇总：全部达标 / N 项达标 M 项需注意 / 都需留意 / 数据不足 |
| 三行判定 | 每行 = 键 + 状态胶囊（良好 / 需注意 / 数据不足）+ 正文 |
| 正文 | **必须写清具体是什么**，不能只给结论。原话要求："注意什么"——空泛结论等于没说 |
| 今日建议 | 饮食 / 运动 / 睡眠各**一条**，必须结合长期目标 + **本周执行情况** |

**代码入口**：`build_headline()` / `_judge_rows()` / `_headline_advice()`
**本周统计**：`build_week_ctx()`（蛋白逐日序列 / 运动连续天数 / 步数序列 / 记录天数）
**趋势短句**：`week_trend_phrase()`（前 3 天均 vs 后 3 天均）

### 头部建议 vs 详细建议

- **头部**（`_headline_advice`）：每类只给最关键一条，因为头部要"一眼看完"
- **详细**（`build_advice`）：完整规则建议，保留全部条目，不删

两者并存，不要合并。

### 数据不足时的诚实口径（重要，勿删）

| 情况 | 正确说法 | 错误说法 |
|---|---|---|
| 三项全无 | "昨天三项数据都不完整，判断不了——先补记录" | 任何带结论的判断 |
| 无饮食记录 | "昨日没有饮食记录，无法判定结构。今日先把三餐拍清楚" | "三项均在参考区间内" |
| 无活动记录 | "本周没有活动记录，无法判断运动节奏" | "本周运动连续 0 天"（那意味着**没记录**，不是**没运动**） |

### 二之一、体重总趋势图（放在三行判定之后、今日建议之前）

一张图回答「**整体减重速度对不对**」，比单日数字有用。顺序是「昨天怎么样 → 整体往哪走 → 今天做什么」。

| 元素 | 含义 |
|---|---|
| 灰点 | 每日实测体重（`note` 含「异常读数」的点剔除） |
| 绿线 + 空心点 | 每 **7 天**均值 |
| 绿虚线 | 目标体重（`weight_loss.goal_kg`） |
| 灰虚线 | 起点体重（`weight_loss.start_kg`） |
| 图注 | 累计降幅 · 最小二乘回归 kg/周 · 距目标 · 已完成百分比 |

**三条口径（决定这条线怎么读，勿改）：**

1. **周窗口从起点起算切，不按自然周**——按自然周会把起点单列成一个只有 1 个点的窗口，视觉上是假尖刺
2. **不满 3 天的窗口不画**，但当日值必须在图注里写明「未计入周均」，否则「今天 X kg」和图上「Y kg」对不上，用户会怀疑数据
3. **斜率一律最小二乘回归**，不用两点相减——端点噪声会被放大 2 倍以上

**降级**：有效称重 < 3 次 → 整块不输出；只有一个完整周 → 只画一个空心点、不画线；未配 `weight_loss.start_date` → 取库里最早一条体重记录的日期。

## 三、② 核心指标总览（D-39 体检化验单样式）

**四列**：项目 | 结论 | 数值 | 参考范围 / 说明

**核心规则：结论列一个词讲明白结果。**

| 状态 | 呈现 |
|---|---|
| 需注意 | 整行浅米色底 + 数值列 `▲` 角标 + 结论词 |
| 达标 | 结论词「达标」，淡化显示，不加底色 |
| 数据不足 | 结论词「数据不足 / 无记录」，灰底 |

### 判定函数

| 函数 | 用途 | 注意 |
|---|---|---|
| `verdict_word(value, lo, hi, higher_better)` | 通用双向阈值 | 需明确 `higher_better` |
| `floor_only_word(value, floor)` | **只需不低于下限**的指标 | ⚠️ 血氧只能用这个 |
| `gap_word(gap, lo_s, hi_s)` | 缺口专用 | 过小=无进展 / 过大=掉肌肉风险 |
| `trend_word(seq, higher_better)` | 趋势判定 | 减重语义：持平 = 需注意 |
| `diet_verdict_words(dq_items)` | 营养结构按项给方向词 | — |

### 已踩过的坑（勿重犯）

1. **血氧判成「过大」**：`verdict_word(99, None, 92)` 会走 `value > hi` 分支判上限，
   而血氧**只有下限、没有上限**。→ 必须用 `floor_only_word()`。
2. **体重「持平」判成达标**：减重期持平 = 没有进展，不能算达标。
   → `trend_word` 对持平返回 warn，文案用「持平未降」。

### 方向词语义约定

- 「过大 / 过小」→ 用于**有上下限的量**（热量缺口、腰围）
- 「过高 / 过低」→ 用于**只有单侧阈值**的指标（摄入热量过低、蛋白质摄入过低）
- 「达标」→ 正常
- 「参考值」→ 公式派生量，本身无好坏（支出热量）

### 每行参考列必须写清阈值来源

- ✗ 「达标线 300–750」
- ✓ 「达标线 300–750 kcal/天（对应周减 0.4–0.8 kg）· 中位约 +1136 · 缺口过大，长期掉肌肉风险」

## 三之一、③ 近 14 天趋势图（D-53）

**12 张小图，分三组**，位置在「核心指标总览」之后、「热量账本」之前——总览给结论，趋势给「往哪走」。

| 组 | 指标 | 绿区含义 |
|---|---|---|
| 身体形态 | 体重、腰围（周频，只画点不连线） | 体重 ≤ 目标 ／ 腰围 ≤ 目标 |
| 营养摄入 | 摄入热量、蛋白质、碳水档位、蔬菜、钙、钠、发酵食物 | 见下 |
| 活动与恢复 | 步数、睡眠、静息心率 | ≥ 步数目标 ／ ≥ 睡眠目标 ／ 40–90 |

达标带的三种语义，**图上必须写清是哪一种**：

| 类型 | 例子 | 图注写法 |
|---|---|---|
| 区间型 | 蛋白 88–118 g、静息心率 40–90 | 「绿区 = a–b」 |
| 下限型 | 蔬菜 ≥ 4 拳、钙 ≥ 800 mg、睡眠 ≥ 7.5 h | 「绿区 = ≥ x」 |
| 上限型 | 钠 ≤ 2000 mg | 「绿区 = ≤ x」 |

**三条硬口径（防止图变成新的说谎工具）：**

1. **缺数不插值、不用 0 顶替**——折线在该日断开，一眼看出「那天没记」
2. **区间型指标画误差棒**：线 = 区间中位，竖线 = 当日上下界。中位**只用于看图**，不当点值结论对外说
3. **判定仍按保守端**：钙按下界判、钠按上界判，与正文完全一致；图上线仍是中位

其它约定：

- **超出区间只把点变橙**，不整条变色——水分波动大的指标整条变橙就看不出走势了
- 摄入热量绿区是 **≥ 下限**（`intake_floor_kcal`），参考摄入量只作灰色虚线，**不当上限**
- 睡眠沿用 `sleep_chart()` 的 `_suspect()` 判据（卧床 > 10 h 且分期占比 < 70% 视为可疑）→ 该点不出图并在图下注明
- 碳水档位是离散量，右上角显示「低 / 中 / 高」，不显示内部编码
- 窗口天数由 `thresholds.trend_chart_days` 控制，默认 14

## 四、热量缺口核算（D-20 口径）

- **BMR** = 10×体重kg + 6.25×身高cm − 5×年龄 + 5（Mifflin-St Jeor）
- **TDEE** = BMR × 1.4 ~ 1.55（`config.weight_loss.activity_factor`）
- **支出**（报告采用）= BMR + `activity_daily.active_kcal`（**已含运动，不再单加 workout.kcal**）
- **缺口** = 支出 − 摄入（摄入是区间 → 缺口也是区间，上下界互换）
- **达标线** 300–750 kcal/天（`deficit_safe_kcal_day`）
- **摄入下限** 1500 kcal（`intake_floor_kcal`），低于此触发红线提示

**交叉验证**：设备口径的「支出」应落在 `BMR×1.4–1.55` 区间内。
超出上界 → 支出可能被高估（手机与设备同日重复上报），或摄入被低估 → **如实标注**。

**减重速率**：`需减 kg ÷ 4.345 周/月 ÷ 月数`
→ 12 kg ÷ 4.345 ÷ 6 ≈ **0.46 kg/周**；÷ 9 ≈ **0.31 kg/周**
（⚠️ 别写成 `÷ 52 ÷ 月数`，那是把"周"当"月"用了两次，会差 15 倍）

**判趋势不判单日**：单日摄入区间可宽达数百 kcal，不可判。缺口与体重都看多日均值。

## 五、⑥ 今日建议（详细版）

`build_advice(ctx)` 分四类输出：**运动 / 饮食 / 睡眠 / 体重**，每类必出。

条目自带机器可核验的 `check`，写进 `data/advice_log.jsonl`（含 `target_date = 次日`）。
次日生成报告时按 `target_date` 取回并逐条核验 → 执行率 = done / (总 − na)。

**必须能落到具体动作**："晚饭后走 20 分钟" ✅　"多运动" ❌

## 六、⑥ 昨日建议执行率（T+1）

自动核验，不需人回填。指标映射见 `eval_check()`：
`steps` / `workout_min` / `veg` / `protein` / `intake_floor` / `carb` /
`sleep_min` / `waist_weekly`

## 七、数据来源诚实性（硬约束）

- 手环源库**不提供设备标识**（MCP 丢弃了 `sid`）→ **分不出手机记的还是手环记的**。
  统一说「活动数据」，**不要说「手环记录」**。
- 营养是**估算**：照片 / 口述口径，误差可达数百 kcal。
  只用于「看见吃了什么、判断饮食结构」，**不用于精确热量核算**。
  报告中不出现"精确摄入 XXX kcal"这类表述。
- 数据不足时如实说"数据不足"，**绝不用估算填满报告**。宁可报告短，不可报告假。

## 七之一、发酵食物（单列维度，不进热量核算）

**为什么单列**：它服务的是肠道菌群，与「六类营养素」不重叠；混进热量/蛋白里会让两个目标互相干扰。

| 项 | 口径 |
|---|---|
| 目标 | `goals.ferment_servings_target`（默认 **2 份/天** 达标，3 份良好） |
| 计数 | 只计**含活菌、吃前没有再加热**的发酵食品 |
| 加热过的不计 | 泡菜下锅、纳豆拌热饭——菌已灭活 |
| 常被误算的不计 | 馒头 / 面包 / 醋 / 酱油 / 豆瓣酱；巴氏杀菌、常温货架产品 |
| 腐乳 | 计入但 10 g 折 1 份，且当日钠预算同步收紧 |
| 记录 | `record_meal.py --ferment <份数> --ferment-desc "<具体是什么>"` |

**呈现**：核心指标总览加一行「发酵食物」；饮食结构表加一项；餐食明细在内容格挂绿色徽标；趋势图有一张「发酵食物」。

**证据**：Wastyk et al., Cell 2021（n=36，10 周 RCT）→ 高发酵饮食组菌群多样性上升、炎症蛋白下降，**剂量依赖**；局限是样本小、周期短、终点为替代指标 → **B+**。原文明确**未确立最小有效剂量**，所以取可持续的 2 份而非试验剂量 6 份。

**边界**：只记录与看趋势，**不做菌群检测、不做医学判断、不推荐益生菌补剂**（补剂属 D 层，永不进建议）。

## 八、安全边界

不下疾病诊断 · 不给药物补剂建议 · 不给极端饮食方案 · **不解读异常心率/血氧/血压数值**。
详见 `safety-boundary.md`。
