# 发布说明 · 1.6.0

**一句话**：日报从「一堆数字」变成「能看出走势」——新增 **12 项指标的 14 天折线图**和**减重总趋势图**；同时把**发酵食物**单列成一项跟踪。

---

## 一、为什么要改

1.5.0 解决了「答案怎么给」。1.6.0 解决「**趋势看不见**」。

旧版日报的每个指标都是当天一个数。问题是：减重期最有价值的信息不是「今天 77.5 kg」，而是「这 14 天在往哪走、走得对不对」。

**单日体重受水分、糖原、钠摄入影响，一天能晃 1–2 kg。** 只看单日，人会一直怀疑自己做错了。所以这一版把「走势」直接画出来，并且把目标区间画在图上——不用读文字，看一眼就知道这几天的点是落在绿区里还是绿区外。

---

## 二、新增：两类图

### 1. 近 14 天趋势（12 张小图）

位置：核心指标总览**之后**、热量账本**之前**。分三组：

| 组 | 指标 | 绿区含义 |
|---|---|---|
| 身体形态 | 体重、腰围（周频） | 体重 ≤ 目标 ／ 腰围 ≤ 目标 |
| 营养摄入 | 摄入热量、蛋白质、碳水档位、蔬菜、钙、钠、发酵食物 | ≥ 1500 kcal ／ 1.2–1.6 g/kg ／ 中低 ／ ≥ 4 拳 ／ ≥ 800 mg ／ ≤ 2000 mg ／ ≥ 2 份 |
| 活动与恢复 | 步数、睡眠、静息心率 | ≥ 8000 ／ ≥ 7.5 h ／ 40–90 |

**建议区间用浅绿带 + 绿虚线画在图上**，超出区间的点变橙色。

三条硬口径（防止图变成新的说谎工具）：

1. **缺数不插值、不用 0 顶替**——折线在该日**断开**，一眼看出「那天没记」
2. **区间型指标画误差棒**：线 = 当日估算区间中位，竖线 = 上下界。**中位只用于看图，不当点值结论**
3. **图上判定与正文判定一致**：钙按下界判、钠按上界判

技术上是**原生 SVG，不引任何前端库**——报告仍是单文件，可离线打开、可直接发。

### 2. 体重总趋势（在「一句话总结」里）

从减重起点画到报告当天：灰点 = 每日实测，绿线 = 每 7 天均值，绿虚线 = 目标。

图注给四个数：累计降幅 · 回归速率（kg/周）· 距目标 · 完成百分比。

**斜率用最小二乘回归，不用「首尾两点相减」**——后者会被端点噪声放大一倍以上。

三条口径：

- 周窗口从**起点起算**切，不按自然周（否则起点会单列成一个只有 1 个点的假尖刺）
- **不满 3 天的窗口不画**，但当日值会在图注里写明「未计入周均」，避免与图上数字对不上
- 有效称重 < 3 次 → 整块不输出

## 三、新增：发酵食物跟踪

**为什么单列**：它服务的是肠道菌群，与「六类营养素」坐标系不同。混进热量/蛋白核算会让两个目标互相干扰。

| 项 | 口径 |
|---|---|
| 目标 | **2 份/天** 达标，3 份良好（可在 config 改） |
| 1 份 | 发酵乳 100 g ／ 发酵豆制品 30 g ／ 发酵蔬菜 50 g ／ 味噌 10 g ／ 发酵饮品 200 ml |
| 计数 | 只计**含活菌、吃前没有再加热**的 |
| 不算 | 加热过的（泡菜下锅、纳豆拌热饭）；馒头面包 / 醋 / 酱油 / 豆瓣酱；巴氏杀菌与常温货架产品 |
| 特例 | 腐乳计入但 10 g 折 1 份，且当日钠要相应减 |
| 录入 | `record_meal.py --ferment 2 --ferment-desc "无糖酸奶 200g"` |

**为什么是 2 份而不是 6 份**：目前唯一的人体 RCT（Wastyk et al., *Cell* 2021，n=36、10 周）用的是约 6 份/天，菌群多样性与炎症蛋白都改善，且**剂量依赖**。但 6 份 ≈ 酸奶 600 g ≈ 400 kcal，在减重预算里塞不下；原文也明确**未确立最小有效剂量**。所以取可持续的 2 份。

证据等级 **B+**（真 RCT，但小样本、周期短、终点是替代指标）。**不做菌群检测、不给益生菌补剂建议。**

## 四、新增：钠的字段化

`meal` 表此前没有钠字段，钠只活在备注的自由文本里 → 无法汇总、无法画图。

本期加 `sodium_mg_low / sodium_mg_high`，**历史行留空、不回填**。回填等于拿今天的估算覆盖当时的口径，属于伪造历史。

代价是钠图头几天是空态，显示「从今天起累积」的占位。

## 五、修掉的问题

| 现象 | 原因 | 修法 |
|---|---|---|
| **`--root` 静默失效**（1.4.0 起就存在，之前被写成「已知限制」） | 脚本会 import `_intake_log`，它带着同一个根目录解析器，**先一步把 `--root` 从 argv 里吃掉**；主脚本再找不到就回落到 `~/health-data`，报一个莫名其妙的「找不到 config」 | 解析成功时写回 `HEALTH_ROOT` 环境变量，后续被导入的脚本直接复用 |
| 新建项目第一份报告的趋势图，左侧空一大段 | 配置模板把减重起点写死成一个很早的日期 | 模板改成留空＝取库里最早一条记录 |
| 长跨度时横轴 3 个日期挤在左端 | 刻度固定取 0/7/14/天 | 跨度 > 24 天改为三等分 |
| 「三项数据都不完整，判断不了」而其中两项明明有结论 | 只要有任一「数据不足」且无「良好」就命中该分支 | 改为「全部不足」才说；混合时写「X、Y 需注意（Z 数据不足，未计入）」 |
| 「已达目标」浅绿区完全看不见 | y 轴下限正好等于目标值，绿区高度被算成 0 px | 去掉该填充只留虚线——零高度的填充比看不见更误导 |
| 碳水档位小图右上角显示「3」 | 离散档位露出了内部编码 | 显示「低 / 中 / 高」 |
| 表格加一列后表头竖排、数字折行 | 10 列把内容列挤没了 | 撤列改挂徽标 + `nowrap` |
| 空数据日仍写「三项均达标」 | 分母把「数据不足」的项也算进去了 | 只算有数据的项 |
| 总览行末尾出现「。。」 | 句号拼接重复 | 统一只在拼接处加一次 |
| **总览表「饮食结构」的数值列被挤成一字一行竖排** | 结论列设计上是「一个词」，这行却把整串短语塞进 118 px 的胶囊，把数值列挤到只剩一个字宽 | 结论列只留一个总词（需调整 / 各项达标），逐项 ✓✗ 看数值列；数值列给足最小宽度 |
| **记了起止时间却被告知「该夜无睡眠记录」** | 只要没有睡眠时长就落到「无记录」分支；但脚本本身允许只记起止（卧床 ≠ 睡着） | 新增「未记时长」分支：照实写入睡/起床时间，并提示补一句时长 |
| 体重输入单位默认成「斤」 | 配置模板沿用了旧习惯 | 默认改 kg（改成斤之前会提示历史读数不自动换算） |

## 八、已知限制

- **钠与发酵食物的历史数据为空**：字段是新加的，没有回填。图上会是断口，这是诚实，不是缺失
- **未配手环的用户**：活动 / 睡眠 / 静息心率三张图会一直是空态
- **手环云端接入仍是第三方逆向项目**（mi-fitness-mcp-cn，MIT，非官方），接口可能因厂商改版失效
- **非 WorkBuddy 宿主上漏记巡检不可信**：没有附件台账，脚本报「没有漏记」的退出码也是 0
- **报告里的营养仍是估算**：区间可宽达数百 kcal，只用于看结构，不用于精确核算
